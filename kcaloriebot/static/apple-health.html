Из бота в Apple Health

Команда на iPhone переносит калории, белки, жиры, углеводы и вес в приложение «Здоровье». Запускайте её вручную на разблокированном iPhone. Сервер хранит историю переноса и при обычном повторном запуске выдаёт только новые показатели.

В этой версии команду нужно один раз собрать в приложении Apple «Команды» по инструкции ниже. Готовой ссылки iCloud для установки пока нет.

1. Подключите бот

  1. В личном чате с ботом откройте Settings → Apple Health → Подключить Apple Health. Можно также отправить /health connect. Если часовой пояс ещё не выбран, сначала выполните /start.
  2. Бот покажет адрес сервера и персональный ключ. По умолчанию первый перенос начинается с начала сегодняшнего дня в часовом поясе дневника. Чтобы включить историю, укажите дату: /health connect 2026-09-01.
  3. Используйте подключение на одном iPhone. Повторное подключение заменяет ключ, сохраняя историю переноса. Для замены ключа в «Командах» просто обновите его текст. Не публикуйте команду вместе с ключом: он предоставляет доступ к вашему экспорту.

2. Создайте команду

Откройте «Команды» → «+», назовите команду KCalorieBot → Здоровье. Названия действий могут немного отличаться в зависимости от языка и версии iOS; рядом указаны английские названия. Добавляйте действия строго в указанном порядке.

  1. Добавьте действие Текст с адресом сервера из бота, включая /health/v1/ в конце. Следом — Задать переменную (Set Variable), имя Сервер.
  2. Добавьте второй Текст с персональным ключом и задайте переменную Ключ.
  3. Добавьте Повторить (Repeat), количество 100. Все действия следующего раздела поместите внутрь этого повторения. Один повтор переносит один показатель, поэтому один приём пищи может занимать четыре повтора.

3. Действия внутри повторения

Получите следующий показатель

  1. Добавьте URL: переменная Сервер, сразу после неё текст next, без пробела. Получится адрес вида https://food.example.com/health/v1/next.
  2. Добавьте Получить содержимое URL (Get Contents of URL). Разверните параметры: метод POST, заголовок Authorization со значением Bearer и переменной Ключ (после Bearer один пробел), заголовок Content-Type = application/json. Тело запроса — JSON, без полей: {}.
  3. Сохраните результат в переменную Ответ. Действием Получить значение словаря (Get Dictionary Value) получите ключ status именно из Ответ.
  4. Добавьте Если (If): status не равно sample. Внутри: если status равен done, покажите уведомление «Перенос завершён»; иначе покажите предупреждение «Перенос остановлен. Отправьте /health боту и проверьте подключение или незавершённую запись». После этого, всё ещё внутри внешнего «Если», добавьте Остановить эту команду (Stop This Shortcut / Stop and Output без результата). Закройте «Если». Любой ответ, кроме sample, должен останавливать команду до записи в Health.

Сохраните в «Здоровье»

  1. Из переменной Ответ получите ключ receipt и сохраните как Квитанция. Из того же Ответ получите ключ sample и сохраните как Показатель.
  2. Из словаря Показатель по отдельности получите ключи type, value, date и задайте переменные Тип, Значение, ДатаТекст. Для каждого действия явно выбирайте исходный словарь Показатель, а не результат предыдущего действия.
  3. Передайте ДатаТекст в Получить даты из входных данных (Get Dates from Input), затем Получить первый объект из списка. Сохраните результат как Дата. Сервер возвращает ISO 8601 с UTC-смещением, например 2026-09-12T09:30:00+00:00; в Москве это 12:30. Не заменяйте эту дату текущей датой.
  4. Добавьте Число = 0 и задайте переменную Записано.
  5. Добавьте пять отдельных блоков Если Тип равно … по таблице. В каждый блок поместите действие Записать данные здоровья (Log Health Sample). Тип данных выберите вручную из списка, значение — переменная Значение, единица — из таблицы, дата начала и, если доступна, дата окончания — переменная Дата. После успешного действия внутри каждого блока задайте Записано = 1.

Калории должны попадать именно в энергию пищи. Не выбирайте активную энергию или энергию покоя. Неизвестные БЖУ сервер пропускает; известный ноль остаётся нулём. Названия блюд и цели питания не переносятся.

После пяти блоков добавьте «Если Записано не равно 1»: предупреждение «Неизвестный показатель», затем «Остановить эту команду». Закройте «Если».

Подтвердите успешную запись

  1. Добавьте URL: переменная Сервер + ack.
  2. Добавьте Получить содержимое URL: POST, те же два заголовка, тело JSON. Добавьте текстовое поле receipt, значение — переменная Квитанция.
  3. Из результата получите status. Если он не равен acknowledged, покажите предупреждение «Подтверждение не получено. Отправьте /health боту» и остановите команду.
  4. Закройте блок «Повторить». После него добавьте уведомление «Перенесено 100 показателей. Запустите команду ещё раз, чтобы продолжить».

Не переносите подтверждение перед действием Health и не добавляйте повтор записи при сетевой ошибке. При сбое команда должна остановиться. Повторить сам запрос ack с той же квитанцией безопасно.

4. Первый запуск и проверка

Для первого запуска временно установите один повтор вместо 100. Разрешите доступ к серверу и запись нужных показателей в «Здоровье». Убедитесь, что перенесённый показатель появился с правильными значением, единицей и временем. Затем верните 100 повторов. При первом появлении каждого нового типа Health может попросить дополнительное разрешение. Сервер подтверждает только получение квитанции от команды; самостоятельно проверить запись на iPhone он не может.

В «Здоровье» откройте «Обзор» → «Питание» или «Параметры тела» → нужный показатель → «Показать все данные». Источником записей будет приложение «Команды». Запускайте перенос только на одном iPhone и не запускайте два экземпляра команды одновременно.

Если перенос прервался

Отправьте /health боту. Он покажет точный показатель, время и команды восстановления. Сначала остановите все запуски команды на iPhone, затем проверьте «Показать все данные» в «Здоровье»:

  • Если показатель уже сохранён, отправьте предложенную команду /health saved …. Повторно записывать его не нужно.
  • Только если показателя нет, отправьте /health retry …, затем запустите команду снова. При отказе в разрешении сначала включите запись для нужного типа в настройках доступа Health.

Так же восстанавливается потерянный ответ сервера: выдача показателя уже могла сохраниться на сервере, даже если iPhone его не получил. Не подтверждайте запись, которой нет, и не выбирайте повтор без проверки.

Если еда или вес изменились после переноса

Перенос остановится, а /health покажет прежнее и новое значение. В «Здоровье» вручную удалите старую запись, созданную этой командой, и при необходимости добавьте новую с указанным временем и значением. Затем отправьте предложенную ботом команду /health corrected …. Это подтверждает выполненное вами исправление; само по себе оно не меняет данные на iPhone. Если изменились несколько БЖУ, исправьте каждый из показателей.

Смена iPhone с сохранённой базой Health не требует сброса истории. Если база Health на новом устройстве пустая или вы удалили уже подтверждённые записи, автоматический повторный импорт этой версии не восстановит их. Отключение интеграции также не удаляет записи из Health.
